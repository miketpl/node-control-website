Find which switch port a MAC or IP is on (any vendor)

Last updated 11 November 2026

Someone hands you a MAC address, or an IP, and asks where it is plugged in. On a mixed estate that means the gateway ARP table, then the MAC table on one switch after another, until you reach an edge port.

[MIKE: confirm or rewrite in your words]

I once spent a day finding one MAC across 10 sites.

This page is the manual method first: the commands, the formats, and the things that catch people out. Then it shows how Find Device in Node Control does the same job.

The addresses below are documentation examples (RFC 5737 and a made-up MAC). Use your own values in the lab.

Start with the IP, if that is what you have

If you were given an IP address, resolve it to a MAC on the gateway first.

On Cisco IOS, IOS-XE and NX-OS:

show ip arp 192.0.2.10

If the address sits in a VRF, add the VRF name:

show ip arp vrf <name> 192.0.2.10

On Junos:

show arp no-resolve | match 192.0.2.10

Take the MAC from that output and look it up in the switching table. If the gateway has no ARP entry, the host may be quiet, in another VRF, or not on this gateway.

Look the MAC up in the address table

Each vendor has its own command and its own MAC format. These are the forms I would try first. They need a check on my lab before this page goes live.

Vendor Command
Cisco IOS, IOS-XE, NX-OS, and Arista EOS show mac address-table address 0011.2233.4455
Juniper Junos show ethernet-switching table | match 00:11:22:33:44:55
Aruba AOS-CX show mac-address-table address 00:11:22:33:44:55
Aruba AOS-S / OS-Switch show mac-address 001122-334455
Dell OS10 show mac address-table address 00:11:22:33:44:55
Extreme EXOS show fdb 00:11:22:33:44:55

If the port is an access port, you have the answer. If it is a trunk, a LAG, or a port-channel, keep going.

Follow the uplink to the edge

A MAC learned on a trunk is usually coming from a downstream switch, not sitting on that port. Check who is on the other end, then hop to that neighbour and run the MAC table command again.

On Cisco and anything that speaks CDP:

show cdp neighbors GigabitEthernet1/0/1 detail

Where you use LLDP (Junos, Aruba, and many mixed fabrics):

show lldp neighbors GigabitEthernet1/0/1 detail

Repeat until the port is an edge port. If the MAC shows on a port-channel or LAG, identify the bundle members and the neighbour on the bundle before you hop. The interface name in those neighbour commands is an example; use the port the MAC table actually returned, in that vendor’s form.

Things that catch people out

  • MAC formats. Cisco dotted (0011.2233.4455), colon-separated (00:11:22:33:44:55), hyphenated, and Aruba’s 001122-334455 are the same address. A paste in the wrong form often returns nothing.
  • Aged-out entries. If the client has been quiet, the MAC may have left the table. A ping from the gateway can refresh ARP and the CAM, but only if the host replies.
  • Port-channels and LAGs. The table may show the bundle, not a member port. Look up the members and the neighbour on the aggregate before you treat it as the edge.
  • Wireless clients. The MAC often appears on the switch port that faces the access point, not on a port of its own. The SSID and AP name live in the wireless system.

How Node Control does it

In Node Control this is Find Device, on the Engineer tab. You paste a list of MAC addresses and IP addresses, one per line. It accepts common MAC formats (colons, dots, hyphens, or none) and dotted-quad IPs.

If you give it an IP, it asks the starting switch — or, on Professional, the site’s saved core switches — for that IP in the ARP table, including VRFs. If none of them holds it, the row says it could not resolve the IP to a MAC.

On Professional you pick a site, or All. Find Device starts from that site’s saved core switches and follows CDP or LLDP into the fabric until it reaches an edge port, or the port of an access point. If you have a Meraki Dashboard API key in Settings, it can also look up Meraki wireless clients and return the network, SSID, AP and last seen.

The results show the edge switch, port, VLAN, neighbour, and the OUI vendor.

On Free, you pick one switch to start from. Find Device follows the trail from there to the edge port, one switch at a time, with no site or cores model. Meraki wireless clients are included on Free as well as Professional.

The Find Device walk is documented for Cisco IOS, IOS-XE and NX-OS, Aruba AOS-CX, HP ProCurve and Aruba OS-Switch, and Arista EOS. The Find Device documentation currently says Juniper Junos, Dell and Extreme are skipped with a clear reason until their output formats are confirmed.
